# Q4.1 Pipeline 设计决策（300-500 字）

**分流策略（三层）**。真实分布（MySQL 实测）决定设计：≤3 分差评 22,754 条中 36.5% 完全无文本，
单词消息仅 2.2% 且多为 "Bom/ok/recomendo" 等正面词（打低分写好话的矛盾样本）。
据此分三层：**L0 规则层**（约 9,000+ 条）——无文本直接占位、高频模板消息
（"Não recebi o produto" 出现 86 次）与极简消息走葡语词典映射，零成本；
**L0.5 规则兜底**——LLM 返回空 issues 时用 5 组高置信关键词模式补漏，
证据取自原文实际子串，不引入幻觉；**L2 LLM 层**——仅约 1.3 万种不同消息进模型，
且消息级去重 + 结果缓存。

**Prompt 设计**。系统提示用葡萄牙语（与输入同语言减少翻译噪声），核心防幻觉机制有三：
`evidence_quote` 必须逐字出自原文（代码层 sanitize 二次校验，空白规范化后不匹配即丢弃
该 issue，试跑实测丢弃 11 条）；类别/severity 白名单；confidence 对歧义文本强制 <0.6。
翻译放字段级：原文葡语引用 + 单独 `evidence_quote_en`，不让模型改写原文。

**批处理**。单条 vs 批量实测对比（glm-4-flash 免费档）：单条 1.3 万次请求在限速下不可行；
批量 16 条/次 + 输出带 `id` 字段按 id 对齐（防漏答导致整批作废——第一版按数组顺序对齐，
长度不符整批失败率 ~17%），缺失条目单条补漏。并发 8 线程 + `$3` 影子成本熔断 +
增量缓存（中断重跑不重复付费）。

**评估设计**。无 ground truth，采用分层抽样 30 条人工标注：按来源分层
（rule/llm/兜底）× 按 issue 类别分层，人工判定 category/severity 是否正确、
evidence_quote 是否忠实原文。指标：类别准确率、证据忠实率（防幻觉的最终检验）、
幻觉丢弃的误杀率。结果见 accuracy_evaluation.md。

**成本**。glm-4-flash 免费档，实际 $0；按 DeepSeek-V3 单价折算影子成本
（输入 $0.27/M + 输出 $1.10/M）约 $0.5——若用付费模型也在预算内。
代价是时间：免费限速下全量约 3 小时，这是"免费换时间"的工程权衡。
